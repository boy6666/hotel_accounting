## 0. 设计原则（先读这个）

1. **一切主数据用户自定义。** 费用项、渠道、房间、佣金率、档位价目、回本参数、城市天气、导入归类规则……**全部可增删改**。数据库里**不允许**存在"写死的枚举业务清单"——原型里的 17 个费用项、6 个渠道、10 间房、回本金额都只是**示例种子**，不是约束。
   **优先自动建档**：费用项、渠道、房号**由 Excel 导入自动识别创建**（智能归类/渠道行识别/房号识别），用户日常不用手工维护；只有不从 Excel 来的东西（房型/楼层/停用状态、档位、佣金率、回本参数）才在设置页手工维护。**可售房间数 = `room` 表启用间数推导**，不再手工填一个笼统数字。
2. **流水表存快照，字典表只管维护。** 月度成本明细记录 `item_name`/`type` 快照，即使以后字典改名/停用，历史报表不受影响。`cost_item_id` 只是关联便利，允许为 NULL（未归类项）。
3. **金额一律 DECIMAL，禁止浮点。** 收入/成本/利润 `(12,2)`，回本/投资 `(14,2)`，佣金率 `(5,4)`（0.1200 = 12%），入住率/预测率 `(5,2)`（百分比数值：85.00 表示 85%）。
4. **到手价口径**：业务表默认存**到手收入** `revenue`；`gross_revenue`（挂牌价收入）与 `commission`（佣金）为可空冗余，便于看板列示，禁止脱离两者单独倒推。
5. **月份统一 `CHAR(7)` = `YYYY-MM`**；日期 `DATE`。唯一键防重导：`(month, channel_id)`、`biz_date`、`(scenario_id, month_seq)` 等。
6. **删除策略**：被历史引用的字典（`cost_item`、`channel`）**软删**（`enabled=0`）；独立可重建的数据（如某月成本明细、未确认导入批次）允许物理删。重导 = 先删该月明细再插入（事务）。
7. **主数据 vs 流水三类都齐**：
   - 主数据（用户维护）：`cost_item` `channel` `room` `pricing_tier` `hotel_config`
   - 月度/日度流水（导入或手录）：`monthly_cost` `daily_occupancy` `monthly_summary` `channel_monthly`
   - 衍生/算法（系统生成）：`pricing_suggestion` `prediction_result` `breakeven_*` `price_calc_scenario`

## 1. ER 总览

```mermaid
erDiagram
  sys_user ||--o{ (登录会话) : ""
  hotel_config ||--|| hotel : "1:1 全局配置"
  room ||--o{ daily_occupied_room : "每日入住明细"
  daily_occupied_room ||--o| daily_occupancy : "按日聚合(冗余)"
  channel ||--o{ channel_monthly : "月度渠道统计"
  cost_item ||--o{ monthly_cost : "月度费用(可NULL快照)"
  import_batch ||--o{ monthly_cost : "导入来源"
  import_batch ||--o{ daily_occupancy : "导入来源"
  pricing_tier ||--o{ pricing_suggestion : "建议价引用档位"
  breakeven_scenario ||--o{ breakeven_cashflow : "逐月现金流"
```

> 营业额核心表的关系：
> - `monthly_summary`（月度汇总头，1 条/月）
> - `monthly_cost` 明细 → 汇总出 `monthly_summary.total_cost`
> - `channel_monthly` 明细 → 汇总出 `monthly_summary.revenue/nights/online_nights`
> - `daily_occupied_room` 逐日记录"哪些具体房间入住" → 聚合成 `daily_occupancy.occupied_rooms` ≈ `monthly_summary.nights`，两者对账抓差房。
> - `room` 表启用间数 = 可售房间数，供入住率/目标倒推/回本共用。

## 2. 表清单

| 表 | 用途 | 归属 |
|----|------|------|
| `sys_user` | 登录账号（单用户但表可扩展） | 主数据 |

| `pricing_tier` | 档位价目字典（平日/周末/平台/节假日） | 主数据 |

| `daily_occupied_room` | 每日实际入住的**具体房间**（biz_date+room_id 唯一） | 流水 |

| `import_mapping_rule` | 智能归类学习规则（原始名→费用项） | 主数据/衍生 |

| `price_calc_scenario` | 目标倒推计算器存参/结果 | 衍生 |

| `app_setting` | 通用 KV（主题、模板版本等） | 主数据 |

## 4. 主数据管理约定（用户自定义是硬需求）

> **自动化优先：能从 Excel 自动拿到的，就不设独立维护界面。**
> - `cost_item`：**导入自动建档**。月度 Excel 成本表 → 旁车识别原始费用名 → 智能归类（`import_mapping_rule`）→ 新名字自动建 `cost_item`。用户只在**导入确认步骤**校正归类，无需日常维护"费用项目录"。
> - `channel`：**导入自动建档**。销售表渠道行自动识别加入字典；设置页**只**提供"改佣金率 / 停用 / 手动新增"，不设完整管理页。
> - `room`：**房号导入自动建档**。每日房态登记/导入出现未建档房号 → 自动建 `room`；房型/楼层/停用走设置页维护（Excel 没有这些）。
> - `pricing_tier`：**不在 Excel 中，必须设置页维护**（档位价目是经营配置）。
> - `hotel_config`：**必须设置页维护**（酒店名/城市/默认佣金率）；**房间数不在此维护**，由 `room` 表推导。
> - 模板下载：导入入口/设置页提供。

| 主数据 | 建档方式 | 维护界面 | 删改影响 |
|--------|----------|----------|----------|
| `cost_item` | 导入自动建档（旁车智能归类） | 仅**导入确认**步骤（改归类/改名），无独立页 | 改名校对历史用 `item_name` 快照，不影响 |
| `channel` | 导入自动建档（渠道行识别） | 设置页：改佣金率 / 停用 / 手动新增 | 改佣金只影响之后录入；历史 `channel_monthly` 已固化 |
| `room` | 房号导入自动建档 | 设置页：房型/楼层/停用/新增/排序 | 停用即退出可售；删房号级联删 `daily_occupied_room` 明细 |
| `pricing_tier` | 人工维护（不在 Excel） | 设置页：增删改/停用 | 被建议价引用则停用而非删 |
| `hotel_config` | 人工维护 | 设置页 GET/PUT 单行 | 房间数 = `room` 表启用计数，实时反映 |
| `import_mapping_rule` | 导入确认流程自动增改 | 无独立页（可间接修正） | 用户手改映射即写新规则 |

> 所有"示例数据"（seed.sql 中的费用项/渠道/档位）**全部可增删改**，只是为了让新装系统开箱可用。前端设置页提供管理入口（见 `04-UI原型说明.md` 之"基础数据管理"）。

## 5. 索引与约束汇总

- 唯一键：`sys_user.username`、`hotel_config.id`(=1)、`room.room_no`、`channel.name`、`cost_item.name`、`daily_occupancy.biz_date`、`daily_occupied_room(biz_date,room_id)`(PK)、`channel_monthly(month,channel_id)`、`monthly_summary.month`、`import_mapping_rule.raw_name`、`pricing_suggestion.biz_date`、`breakeven_cashflow(scenario_id,month_seq)`、`app_setting.skey`

- 外键：`monthly_cost.cost_item_id → cost_item(id) ON DELETE SET NULL`；`channel_monthly.channel_id → channel(id)`（只能软删）；`daily_occupied_room.room_id → room(id) ON DELETE CASCADE`；`breakeven_cashflow.scenario_id → breakeven_scenario(id) ON DELETE CASCADE`
- 所有表 `created_at/updated_at DEFAULT CURRENT_TIMESTAMP [ON UPDATE CURRENT_TIMESTAMP]`
