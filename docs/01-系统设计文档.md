## 1. 项目目标

一个**单用户自用**的轻量系统，解决小规模酒店（示例：10 间房）的日常经营问题：

1. **记账闭环**：月度成本 Excel 一键导入 + 智能归类；每日房态登记（**按具体房间**：哪天哪几间，非笼统几间）；月度销售（渠道流水）录入/导入。
2. **经营看板**：收入/成本/利润/入住率/渠道占比，趋势、环比、同比图表。
3. **对账**：每日房态（具体房间汇总的间夜数）↔ 渠道间夜（渠道流水合计）自动核对，**抓"中介差房"**。
4. **预测**：统计模型（日历 + 天气 + 节假）预测 + LLM 解读，**不做小模型拟合预测**（可插拔引擎）。
5. **定价**：三合一 —— 档位价目表 / 目标倒推计算器 / 临近日逐日建议价。
6. **回本测算**：含贷款、利息、逐月现金流。

**核心目标**（长期）：收益管理 / 动态定价。

### 2.1 分进程边界

| 进程 | 技术 | 职责（只做这些） |
|------|------|------------------|
| 前端 | Vue 3 + Vite + ECharts | 渲染 7 大模块页面；只经 `/api` 与主后端交互，**不直接调 Python、不直连 MySQL** |
| 主后端 | Java 17 / Spring Boot 3 | 全部业务 API、JWT 认证、CRUD、汇总/环比/同比计算、**对账逻辑**、导入编排（调旁车解析） |
| 旁车 | Python 3.11 / FastAPI | 纯"重计算/外部依赖"：Excel 解析、费用智能归类、时序预测、DeepSeek 请求、（三期）弹性小模型。不接触 JWT/权限 |
| 存储 | MySQL 8（utf8mb4） | 唯一持久层；每日备份 |

**职责红线**

- 主后端不调 DeepSeek、不解析 xlsx；旁车不提供业务写接口（只被主后端调用，内部服务：`http://127.0.0.1:8001/api/*`，仅监听回环）。
- 前端永远看不到旁车地址。

## 5. 核心数据流

### 5.1 月度记账闭环（Excel 导入）

```
用户修改「月度记账模板.xlsx」(由 generate_monthly_template.py 生成)
      │
      ▼  POST /api/imports  (multipart 上传)
[主后端] 记录 import_batch(status=uploaded) → 调用旁车 /api/parse
      │
      ▼ [旁车] openpyxl 解析三张表：当月成本 / 每日房态（日期×房号）/ 当月销售利润
      │        智能归类：原始费用名 → cost_item（带置信度，走 import_mapping_rule）
      ▼  返回结构化 JSON + 归类建议
[主后端] import_batch(status=mapped) 暂存；返回给前端"确认归类"页
      │
      ▼  POST /api/imports/:id/confirm  （用户确认/手动改归类）
[主后端] 落库：monthly_cost / daily_occupied_room（房号明细 → 刷新 daily_occupancy 聚合）
         / monthly_summary + channel_monthly；费用项/渠道/未建档房号自动建档
         对账：daily_occupancy 合计 vs channel_monthly 间夜 → reconcile_status
         返回导入结果摘要
```

### 5.2 对账（差房检测）

- 口径：**房夜**（每日房态 `occupied_rooms` 求和） vs **间夜**（渠道流水 `nights` 求和）。
- 规则：`diff = daily_occupancy 合计 − channel_monthly.nights 合计`。
  - `diff == 0` → `matched`；
  - `diff != 0` → `diff`（差异值记入，提示排查"中介差房"：渠道即使报 0 间夜，房态也可能显示住了）。
- 差异只标记，不自动改数。

### 5.3 佣金口径（全局约定，API/库/报表统一）

- 入库与报表一律用**到手价**（酒店实际收到的钱）。
- 每个渠道维护 `commission_rate`：线上渠道记账→**挂牌价 = 到手价 / (1 − 佣金率)**；前端展示线上"挂牌=到手×(1+r)"列。
- 示例（原型）：携程佣金 12%、美团 12%、飞猪/去哪儿 10%、抖音/其它 10%、前台散客 0、协议/中介 0。

### 5.4 预测 / 定价链路

```
[主后端] POST /api/prediction/generate { month, metric }
      │  → 旁车 /api/predict（统计模型：日历 + 天气(按 city) + 节假日）
      ▼  返回预测值 + 置信区间
[旁车]  → DeepSeek（解读趋势/给经营提示，附历史数据摘要，不含敏感字段）
      ▼
[主后端] 落库 prediction_result + llm_interpretation
      │
[主后端] POST /api/pricing/suggestions/generate
      │  → 档位定价表 + 预测入住率 → 逐日建议价（周末/平日/节假日）
      ▼  落库 pricing_suggestion，前端按日期渲染
```

## 6. 接口约定速览（详见 `03-API文档.md`）

- 前缀：`/api`；JSON 收发；`charset=utf-8`。
- 信封：`{ "code": 0, "message": "ok", "data": <业务数据> }`（`code≠0` 为错误，见错误码表）。
- 认证：`Authorization: Bearer <JWT>`，登录 `POST /api/auth/login` 获取。
- 分页：`page` / `pageSize`，返回 `{ list, total, page, pageSize }`。
- 月份：一律 `YYYY-MM`（如 `2026-08`）；日期：`YYYY-MM-DD`。
- 接口按模块分组：认证 / 看板 / 成本 / 渠道 / 利润 / 房态 / 定价·预测 / 回本 / 导入 / 设置。

## 8. 非功能需求

- **单用户**：权限模型最小化（登录 + JWT 即可）；预留 `sys_user` 表，不做角色。
- **数据完整性**：所有 `DECIMAL` 金额禁止浮点；统一 `(12,2)`/`(14,2)`；外键约束；唯一键防重导。
- **备份**：每日 mysqldump，保留 30 天；异地一份。
- **时区/日期**：本地时间；金额元，两位小数；千分位展示归前端。
- **安全**：密码 BCrypt；JWT 短期 + 刷新；DeepSeek 出网只送聚合摘要（费用名/数字），不送身份证类、政治/安全敏感字段。
- **可观察**：Java 与旁车各记日志文件，保留 14 天；旁车故障时主后端接口返 `50100`，前端给"智能服务暂不可用，导入仍可用手动归类"降级提示。
- **天气预测**：旁车调用免费天气接口（聚合摘要即可），失败则预测降级为日历+节假日。
