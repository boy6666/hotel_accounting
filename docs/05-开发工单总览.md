## 2. 全局公共契约（三方必须先对齐，不要各自发挥）

1. **信封**：所有主后端 HTTP 响应 `{ "code": 0, "message": "ok", "data": … }`；`code≠0` 为业务错误，错误码见 03 §3。前端 axios 拦截器统一拆包。
2. **认证**：`Authorization: Bearer <JWT>`；登录 `POST /api/auth/login`（admin/admin123，bcrypt）。单用户无角色。
3. **日期格式**：本地时区；`YYYY-MM`（月）、`YYYY-MM-DD`（日）；`from/to` 闭区间。
4. **金额**：DB 一律 `DECIMAL`；**JSON 中金额以字符串传输**（避免浮点）；千分位格式化归前端展示层。
5. **枚举**：以 `seed.sql` 为准——费用类型 `fixed|variable|one_time`；渠道类型 `online|offline`；数据来源 `manual|import|mapping`；批次状态 `uploaded|parsed|mapped|confirmed|failed`；对账状态 `none|matched|diff|unchecked`。企业不写死新枚举值进代码（都是字典）。
6. **佣金口径**：入库与报表一律到手价；线上挂牌价 = 到手价/(1 − 佣金率)，前端展示「挂牌=到手×(1+r)」列。
7. **可售房间数** = `room` 表 `enabled=1` 计数（**不是**手填数字）；供入住率 / 目标倒推 / 回本共用。
8. **自动化优先**：费用项、渠道、**房号**在导入 confirm 时自动建档；设置页只维护导入无法获知的信息（房型/楼层/停用、档位、佣金率、酒店配置）。
9. **旁车边界**：FastAPI 只监听 127.0.0.1、无 JWT、只被主后端调用（03 §14）；对外不可达。前端**永远不直接调旁车**。
10. **降级**：旁车故障 → 主后端返 `50100`；前端显示「智能服务暂不可用，仍可手动归类/纯日历预测」。DeepSeek 出网只送聚合摘要，不送身份证类/政治/安全敏感字段、完整个人数据。

## 3. 三方边界与依赖

```
┌──────────┐  HTTP/JWT   ┌───────────────────────┐  127.0.0.1   ┌────────────────┐
│ 前端 Vue3 │ ─────────▶ │ Java Spring Boot 主后端 │ ────────────▶ │ Python FastAPI  │
│ (8 页面)  │ ◀───────── │ REST + MySQL + 编排      │ ◀──────────── │ 旁车(解析/归类/预测)│
└──────────┘  {信封}     └───────────────────────┘  {信封,无JWT}  └────────────────┘
```

- **前端只认主后端**（Vite dev proxy：`/api` → `http://localhost:8080`）。
- **主后端编排导入**：上传后调旁车 `/api/parse`，把解析结果存 `import_batch`，confirm 时落库三表 + 自动建档 + 刷新汇总 + 对账。
- **旁车一期无状态**：不碰数据库；归类建议（`/api/categorize`）只是算法输出，学习规则持久化由主后端在 confirm 时写 `import_mapping_rule`。
- **汇总/重算**（`monthly_summary`、`daily_occupancy` 聚合）全部由**主后端**负责刷新；旁车不写库。

**并行启动顺序建议**（不阻塞，只定优先级）：
1. 旁车（最独立，定义了解析/归类的输入输出）；
2. 主后端骨架 + 数据线；
3. 前端（可先用 seed 数据 mock 页面结构，后端字段落地后接 axios）。

## 4. 分期边界（重要）

- **一期（已交付 2026-08-24）**：记账闭环 + 看板 + 对账。覆盖：登录、主数据（房间/档位/渠道佣金/酒店配置）、成本导入+手动、每日房态（具体房间）、渠道流水、月度汇总、首页看板、对账（差房）。

- **三期（预留）**：弹性定价小模型、OTA API、更多报表插件。
